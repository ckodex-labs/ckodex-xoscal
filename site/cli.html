xoscal & xoscal-ctl User Guide

xoscal is the unified 24-command CLI for local NIST OSCAL 1.2.3 authoring, validation, sovereign framework intelligence, OWL/JSON-LD property graph queries, resilient threat feeds, UTCP v1.0.1 agent tooling, and offline review workflows. xoscal-ctl is installed alongside xoscal as a backward-compatible alias supporting identical subcommands and flags. Release builds disable CGO. Installation requires separate provenance verification; this guide does not establish a particular release’s signing or execution results.

Pinned Installation

Choose an explicit release tag and its full source commit. Use the installer from a reviewed checkout of that revision, together with the release’s release-manifest.json and release-manifest.sigstore.json. Python 3.9+ and GitHub CLI are required. The installer verifies the manifest’s GitHub release workflow identity, tag and source, then checks the exact archive bytes before installation.

# Set RELEASE_TAG and SOURCE_REVISION to independently reviewed release values.
sh scripts/install.sh \
  --release "$RELEASE_TAG" --source "$SOURCE_REVISION" \
  --manifest release-manifest.json --bundle release-manifest.sigstore.json \
  --prefix "$HOME/.local" --dry-run
# Omit --dry-run to install xoscal, xoscal-ctl, xoscal-backup, and xoscal-gateway.

Linux and macOS have separate AMD64 and ARM64 archives. There is no universal macOS binary. Each verified GoReleaser archive contains five binaries (xoscal, xoscal-ctl, xoscal-server, xoscal-backup, and xoscal-gateway), and scripts/install.sh atomically installs the four client and gateway binaries (xoscal, xoscal-ctl, xoscal-backup, and xoscal-gateway) while xoscal-server remains in the verified archive. Missing or invalid proof prevents installation. Add the prefix’s bin directory to PATH. See the installation contract for proof download and offline archive steps.

1. quickstart & doctor — Onboarding & Rule 36 Diagnostics

quickstart inspects the current repository and prints recommended sovereign workflow steps. doctor (alias diagnostics) executes Rule 36 checks across 8 subsystems: host runtime substrate, embedded OSCAL 1.2.3 Tier-1 schema engine, all 36 sovereign/international frameworks, pure-Go SQLite Knowledge Graph, optional Tier-2 oscal-cli, Web Studio loopback availability, UTCP v1.0.1 manual conformance, and OWL/JSON-LD unified property graph reconciliation.

xoscal quickstart
xoscal doctor
xoscal doctor -json
Command / FlagTypeDefaultDescription
quickstartcommand—Scans current working directory and reports framework count, schema version, and next steps.
doctor -jsonboolfalseEmits machine-verifiable Rule 13 Decision and Evidence trace JSON; exits 1 if any check fails.

2. init — Repository Scaffolding

Scans application source trees (Go, Python, TypeScript, Rust, Docker, Kubernetes, Terraform) and deterministically maps project characteristics to an OSCAL 1.2.3 Component Definition. All UUIDs are synthesized via RFC-4122 UUIDv5 using the DNS namespace and the canonical repo URN.

xoscal init -dir <path-to-repo> -framework nist-sp-800-53-rev5
FlagTypeDefaultDescription
-dirpath.Root directory of the codebase to analyze.
-frameworkstringnist-sp-800-53-rev5Compliance framework baseline (supports all 36 registered IDs and aliases). Writes component-definition.json and .xoscal/xoscal.yaml.

3. verify / check — Vector State Verification

Evaluates artifacts against the official embedded OSCAL 1.2.3 schema and calculates the multi-dimensional trust vector S(e,t) = <P, V, A, C, E, L, τ>. When -file is omitted, verify (and its CI alias check) auto-discovers standard artifacts in the working directory or .xoscal/. Violations of mandatory security invariants dominate composite scores, strictly preventing binary false-positive theater.

xoscal verify -file <oscal-model.json> -evidence-dir ./evidence
# Auto-discover local artifact or run via CI/pre-commit alias:
xoscal check -json
FlagTypeDefaultDescription
-filepathauto-discoverPath to OSCAL JSON artifact (accepts positional file argument).
-jsonboolfalseEmit the vector state as JSON; default output is a formatted posture table.
-evidence-dirpathemptyOptional evidence directory with SHA-256 sidecars. Failed or quarantined lifecycle returns exit code 3; evaluation errors return 1.

4. validate — Standalone Schema & Integrity Validation

Use validate to check an OSCAL 1.2.3 document against the embedded official JSON schema, with optional deep semantic reference and UUID integrity validation (-integrity). -kind optionally selects catalog, profile, ssp, component-definition, assessment-plan, assessment-results, poam, or mapping; otherwise the root property determines the kind. Invalid results return exit code 3; read or configuration errors return 1.

xoscal validate -file component-definition.json -kind component-definition
xoscal validate ssp.json -integrity
xoscal help
xoscal verify -h

This guide’s examples run locally and do not submit evidence or send review messages automatically.

5. frameworks, verify-parity, seed, generate & ingest — 36 Sovereign Baselines

Manages all 36 registered national and international frameworks (16,237 controls across Canada, US, Germany, France, EU, UK, Estonia, and International), deterministic 7-layer OSCAL 1.2.3 artifact projection with SHA-256 sidecars, verbatim parity checks (verify-parity), Knowledge Graph seeding (seed), snapshot artifact generation (generate), and regulatory requirement ingestion (ingest).

xoscal frameworks list -jurisdiction ca -json
xoscal frameworks export -out data/frameworks -framework cccs-itsp-10-033
xoscal verify-parity -dir data/frameworks -strict -markdown
xoscal seed -dsn oscal.db -snapshot baseline
xoscal generate -dsn oscal.db -snapshot baseline -framework cccs-itsp-10-033 -out ./oscal-out -validate
xoscal ingest -dsn oscal.db -input requirements.json -framework eu-ai-act

9. utcp — Universal Tool Calling Protocol (UTCP v1.0.1)

Generates and validates native UTCP v1.0.1 discovery manuals for 18 zero-wrapper xOSCAL tools across http, cli, and grpc call templates, produces utcp-mcp bridge configurations for Model Context Protocol hosts, and emits ready-to-run client harnesses for five language ecosystems.

xoscal utcp manual -protocols all -out utcp.json
xoscal utcp validate -file utcp.json -json
xoscal utcp mcp-config -utcp-config-out .utcp_config.json -out mcp.json
xoscal utcp sdk -target python-utcp -out client.py
xoscal utcp ecosystem -json
SubcommandKey FlagsDescription
utcp manual-protocols (http, cli, grpc, all), -base-url, -grpc-host, -bin, -auth-env, -extended, -outEmits strict UTCP v1.0.1 manual JSON (or extended envelope) covering all 18 native tools.
utcp validate-file, -jsonValidates a supplied UTCP manual JSON file (or built-in manual) and prints its conformance SHA-256 digest.

10. serve, ui, completion & version — Local Web Studio & Shell Integration

serve (and ui, which passes -open automatically) starts an embedded, zero-dependency local HTTP explorer for browsing all 36 frameworks, searching controls, viewing transition deltas, querying the property graph, and serving /.well-known/utcp. completion emits native autocompletion scripts for bash, zsh, or fish.

xoscal serve -host 127.0.0.1 -port 8080 -open
xoscal ui
source <(xoscal completion zsh)
xoscal version
Command / FlagDefaultDescription
serve / ui127.0.0.1:8080Accepts -host, -port, and -open; automatically falls back across ports 8081..8089 if busy.
completion [bash|zsh|fish]—Writes dynamic completion script bound to the invoking binary name (xoscal or xoscal-ctl).
version—Prints CLI version metadata and exits.

11. diff — GitOps PR Compliance Diff

Computes structural and semantic differences between two OSCAL documents (such as main vs feature-branch). The optional Markdown report can be added to a CI step summary or a separately authorized pull request comment.

xoscal diff -base baseline.json -head candidate.json -markdown -fail-on-regression
FlagTypeDefaultDescription
-basepathmain.component-definition.jsonBaseline OSCAL document (e.g., target branch state).
-headpathcomponent-definition.jsonCandidate OSCAL document under review.
-markdownboolfalseEmit a Markdown report for CI output.
-fail-on-regressionboolfalseExit code 3 if a compliance regression is detected.

12. tabular — Spreadsheet Bridge

Transforms hierarchical OSCAL 1.2.3 documents into flat, standardized RFC-4180 CSV tables for compliance teams and spreadsheets, with re-import into a supplied base document. Review the resulting artifact before using it as evidence.

# Export to CSV
xoscal tabular export -in ssp.json -out controls.csv

# Import modified CSV back into OSCAL
xoscal tabular import -in controls.csv -base ssp.json -out updated-ssp.json
SubcommandKey FlagsDescription
export-in, -outExtracts implemented requirements, control IDs, statements, and statuses.
import-in, -base, -outApplies spreadsheet updates to base document and re-validates schema.

13. derogate — Risk Acceptance Lifecycle

Constitutional Rule 23: Accepted risk does not rewrite history. Derogations attach explicit authority, justification, compensating controls, and a non-negotiable TTL. Expired derogations immediately decohere and flip posture vectors back to negative valence.

xoscal derogate add \
  -control "ac-2" \
  -reason "Legacy LDAP sync migration in progress" \
  -authority "urn:ckodex:authority:ciso:sec-board" \
  -ttl-days 30 \
  -compensating "sc-7,au-2"
ActionDescription
addRecords a control, authority, reason and expiry in .xoscal/derogations.json.
listLists active, revoked and expired derogations.
revoke -id <id>Revokes a recorded derogation and saves the store.
