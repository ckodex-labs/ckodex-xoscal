xoscal-ctl User Guide

The xoscal-ctl binary provides local OSCAL 1.2.3 authoring, validation and review workflows. Release builds disable CGO. Installation requires separate provenance verification; this guide does not establish a particular release’s signing or execution results.

Pinned Installation

Choose an explicit release tag and its full source commit. Use the installer from a reviewed checkout of that revision, together with the release’s release-manifest.json and release-manifest.sigstore.json. Python 3.9+ and GitHub CLI are required. The installer verifies the manifest’s GitHub release workflow identity, tag and source, then checks the exact archive bytes before installation.

# Set RELEASE_TAG and SOURCE_REVISION to independently reviewed release values.
sh scripts/install.sh \
  --release "$RELEASE_TAG" --source "$SOURCE_REVISION" \
  --manifest release-manifest.json --bundle release-manifest.sigstore.json \
  --prefix "$HOME/.local" --dry-run
# Omit --dry-run to install after the same checks.

Linux and macOS have separate AMD64 and ARM64 archives. There is no universal macOS binary. Only xoscal-ctl is installed; each verified archive also contains xoscal-server and xoscal-backup. Missing or invalid proof prevents installation. Add the prefix’s bin directory to PATH. See the installation contract for proof download and offline archive steps.

1. init — Repository Scaffolding

Scans application source trees (Go, Python, TypeScript, Rust, Docker, Kubernetes) and deterministically maps project characteristics to an OSCAL 1.2.3 Component Definition. All UUIDs are synthesized via RFC-4122 UUIDv5 using the DNS namespace and the canonical repo URN.

xoscal-ctl init --dir <path-to-repo> --framework nist-sp-800-53-rev5
FlagTypeDefaultDescription
--dirpath.Root directory of the codebase to analyze.
--frameworkstringnist-sp-800-53-rev5Compliance framework baseline. Writes component-definition.json and .xoscal/xoscal.yaml within the selected directory.

2. verify — Vector State Verification

Evaluates artifacts against the official embedded OSCAL 1.2.3 schema and calculates the multi-dimensional trust vector S(e,t) = <P, V, A, C, E, L, τ>. Violations of mandatory security invariants dominate composite scores, strictly preventing binary false-positive theater.

xoscal-ctl verify --file <oscal-model.json> --evidence-dir ./evidence
# Add --json for machine-readable output.
FlagTypeDefaultDescription
--filepathcomponent-definition.jsonPath to OSCAL JSON artifact to evaluate.
--jsonboolfalseEmit the vector state as JSON; default output is a table.
--evidence-dirpathemptyOptional evidence directory with SHA-256 sidecars. Failed or quarantined lifecycle returns exit code 3; evaluation errors return 1.

Standalone Schema Validation

Use validate to check an OSCAL document against the embedded official JSON schema. The --file path is required; --kind optionally selects catalog, profile, ssp, component-definition, assessment-plan, assessment-results, poam or mapping. Otherwise the root property determines the kind. Invalid schema results return exit code 3; read or configuration errors return 1.

xoscal-ctl validate --file component-definition.json --kind component-definition
xoscal-ctl help
xoscal-ctl verify -h

Use command help for additional generate, ingest, frameworks and seed workflows. This guide’s examples do not submit evidence or send review messages automatically.

3. diff — GitOps PR Compliance Diff

Computes structural and semantic differences between two OSCAL documents (such as main vs feature-branch). The optional Markdown report can be added to a CI step summary or a separately authorized pull request comment.

xoscal-ctl diff --base baseline.json --head candidate.json --markdown --fail-on-regression
FlagTypeDefaultDescription
--basepathmain.component-definition.jsonBaseline OSCAL document (e.g., target branch state).
--headpathcomponent-definition.jsonCandidate OSCAL document under review.
--markdownboolfalseEmit a Markdown report for CI output.
--fail-on-regressionboolfalseExit code 3 if a compliance regression is detected.

4. tabular — Spreadsheet Bridge

Transforms hierarchical OSCAL 1.2.3 documents into flat, standardized RFC-4180 CSV tables for compliance teams and spreadsheets, with re-import into a supplied base document. Review the resulting artifact before using it as evidence.

# Export to CSV
xoscal-ctl tabular export --in ssp.json --out controls.csv

# Import modified CSV back into OSCAL
xoscal-ctl tabular import --in controls.csv --base ssp.json --out updated-ssp.json
SubcommandKey FlagsDescription
export--in, --outExtracts implemented requirements, control IDs, statements, and statuses.
import--in, --base, --outApplies spreadsheet updates to base document and re-validates schema.

5. derogate — Risk Acceptance Lifecycle

Constitutional Rule 23: Accepted risk does not rewrite history. Derogations attach explicit authority, justification, compensating controls, and a non-negotiable TTL. Expired derogations immediately decohere and flip posture vectors back to negative valence.

xoscal-ctl derogate add \
  --control "ac-2" \
  --reason "Legacy LDAP sync migration in progress" \
  --authority "urn:ckodex:authority:ciso:sec-board" \
  --ttl-days 30 \
  --compensating "sc-7,au-2"
ActionDescription
addRecords a control, authority, reason and expiry in .xoscal/derogations.json.
listLists active, revoked and expired derogations.
revoke --id <id>Revokes a recorded derogation and saves the store.

6. bundle-export — Air-Gapped Bundles

Packages full compliance packages for offline auditor consumption in high-security SCIFs. Contains complete OSCAL JSON models, linked evidence files, individual SHA-256 sidecars, and an embedded zero-dependency WebCrypto HTML viewer that verifies digests locally inside an air-gapped web browser.

xoscal-ctl bundle-export --in ssp.json --evidence-dir ./evidence --out audit-bundle.tar.gz
FlagTypeDefaultDescription
--inpathcomponent-definition.jsonOSCAL document to bundle.
--evidence-dirpathemptyOptional directory containing raw evidence files.
--outpathaudit-bundle.tar.gzArchive output path.
