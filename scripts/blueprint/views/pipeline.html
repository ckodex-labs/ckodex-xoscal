Dagger pipeline — CI as OSCAL evidence generation

Every Dagger function is an evidence-producing step. Every GitHub Actions workflow is a journey that chains those steps. Every output maps to an OSCAL touchpoint. The pipeline is the evidence generation layer; the portal is the evidence presentation layer. No stage claims to be signed when it is not.

illustrative contract — requires hosted proof Dagger produces every artifact, analysis result and digest manifest upfront. The existing hosted release.yml identity attests the payload manifest; Dagger verifies it before rendering the final site. Hosted Actions then attests the final manifest, and Dagger checks every final byte before promotion. This Design Blueprint supplies no signing result. Configuration, a digest, or a green local gate cannot establish hosted verification.
