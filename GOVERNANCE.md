# OSCALiFY Governance

## Overview

OSCALiFY is an open-source project governed by the CKODEX community. This document outlines the governance structure, decision-making process, and community guidelines.

## Project Maintainers

The project is maintained by the CKODEX team:

- **Project Lead**: CKODEX Team
- **Technical Committee**: CKODEX Engineering

## Roles and Responsibilities

### Maintainers

- Review and merge pull requests
- Manage releases
- Ensure code quality and security
- Guide technical direction
- Respond to security reports

### Contributors

- Submit bug reports and feature requests
- Submit pull requests
- Participate in discussions
- Follow the code of conduct
- Test releases

## Decision Making

### Technical Decisions

Technical decisions are made by consensus among maintainers. In case of disagreement, the Project Lead makes the final decision.

### Feature Requests

Feature requests are evaluated based on:
- Alignment with project goals
- Community demand
- Implementation complexity
- Security implications
- Maintenance burden

### Release Process

Releases follow semantic versioning:
- **Major**: Breaking changes
- **Minor**: New features, backward compatible
- **Patch**: Bug fixes, backward compatible

Release process:
1. Create release branch from develop
2. Update CHANGELOG.md
3. Tag release
4. Build and publish artifacts
5. Merge to master
7. Announce release

## Security

Security issues are handled with priority:
- Critical issues: Patch within 48 hours
- High severity: Patch within 1 week
- Medium severity: Patch within 2 weeks
- Low severity: Patch in next release

See [SECURITY.md](SECURITY.md) for reporting guidelines.

## Community Guidelines

### Communication

- Be respectful and constructive
- Focus on what is best for the community
- Show empathy towards other community members
- Welcome newcomers and help them learn

### Code of Conduct

All contributors must follow the [Code of Conduct](CODE_OF_CONDUCT.md).
Violations will be addressed by the maintainers.
